# Свежие релизы Meshtastic

`prepare-release` получает исходники опубликованного релиза из официального
репозитория Meshtastic и применяет выбранные патчи MeshMemo в новой папке.
Это патчинг **исходников**, а не изменение скачанного `.bin`.

## Использование

```sh
meshmemo-builder list-releases --channel all --limit 10
meshmemo-builder prepare-release --board tbeam-s3-core --destination .work/fresh-stable
```

Предварительные релизы выбираются явно:

```sh
meshmemo-builder prepare-release --board heltec-v3 --channel preview --release latest --destination .work/fresh-preview
```

Можно указать точный опубликованный тег вместо `latest`. Ветки, произвольные URL
и коммиты не принимаются. Канал должен соответствовать тегу. UA22, кириллица и
таймер экрана выключены, пока не переданы `--ua22`, `--cyrillic`,
`--display-timeout`. Ограничения опций платы сохраняются. В мастере есть пункт
«Получить свежий релиз и применить патчи».

Через `--firmware-source` и `--protobuf-source` можно использовать локальные
Git-репозитории. Выбор опубликованного релиза всё равно проверяется через GitHub;
локальный firmware должен содержать тег и коммит, protobufs — коммит подмодуля.

## Проверки и отчёт

1. Для stable/latest используется официальный GitHub latest; preview выбирается
   по дате публикации среди последних 300 релизов. Ошибки сети и лимиты API
   останавливают операцию, без незаметного перехода на кеш или другой канал.
2. Тег закрепляется полным SHA и проверяется после клонирования. SHA protobufs
   берётся из gitlink firmware, а не из текущей ветки protobufs. URL репозиториев
   задаются установленным каталогом.
3. Каждый патч проходит `git apply --check` и `git apply`. При конфликте операция
   останавливается. Конфликтные участки автоматически не переписываются.
4. Конфигурации, определения плат, варианты, встроенные библиотеки и скрипты
   сборки сравниваются с Git-объектами базовой версии. Изменение этих входов
   запрещает использование старого lock. Проверка намеренно консервативна:
   изменение неиспользуемой платы тоже может потребовать нового lock.
5. Перед сборкой повторно проверяются план, коммиты, gitlink, отпечаток входов
   сборки и хеши подготовленных исходников.

`release.json` содержит точные SHA, изменения входов сборки и статусы патчей:
`applied`, `conflict`, `not-run`. `prepare.json` получает статус `prepared` только
после применения всего набора, копирования payloads и записи хешей. Частичный
результат сохраняется для анализа; повторный запуск требует новую папку.

| Код завершения CLI | Результат |
| --- | --- |
| 0 | Исходники подготовлены, совместимый lock доступен. Компиляция ещё не выполнялась. |
| 1 | Ошибка сети, входных данных, конфликта патча или подготовки. |
| 2 | Исходники подготовлены, но изменились входы сборки и нужен новый lock. |

При коде 0 дальнейшие команды прежние:

```sh
meshmemo-builder fetch-dependencies --workspace .work/fresh-stable --cache .cache/dependencies
meshmemo-builder bootstrap --workspace .work/fresh-stable --cache .cache/dependencies --destination .work/rt-fresh
meshmemo-builder build --workspace .work/fresh-stable --runtime .work/rt-fresh --output dist/fresh
```

Для полной сборки нужны Windows AMD64 и Python 3.12.14. Если lock не подходит,
`fetch-dependencies`, `bootstrap` и `build` отказываются продолжать. Отчёт и
исходники позволяют сопровождающему адаптировать патчи и зарегистрировать
проверенные зависимости новой версии.

## Статус совместимости

Совпадение с зарегистрированными firmware/protobufs сохраняет прежний план и
build ID. Новый релиз получает экспериментальный план и build ID, включающий
коммиты, набор патчей и отпечаток входов сборки. HELLO сообщает фактический
firmware SHA. Совместимый lock означает возможность попытки сборки; успешная
компиляция не подтверждает USB, радио и экран. `plan-update` блокирует предложение
записи экспериментального релиза до включения проверенного профиля в каталог.

## Проверка 2026-10-01

- Stable `v2.7.26.54e0d8d`: получен через GitHub API, патчи применены, план
  совпадает с зарегистрированным 2.7.26 и совместим с прежним lock.
- Preview `v2.8.0.47db0e3`: firmware
  `47db0e3020a608e06fb65cce70cd2f093021bd82`, protobufs
  `7b2464c9b8c1521f93852261e4123826e5b25e11`. Обнаружен конфликт
  `0002-usb-diagnostics.patch` в SerialConsole, PhoneAPI и сгенерированном
  `mesh.pb.h`; изменились и входы сборки. Эта версия **не поддерживается для
  готовой сборки** до переноса USB-интеграции и проверки нового окружения.
- Интеграционные тесты создают совместимый коммит поверх 2.7.26 и проверяют
  реальные патчи, смену build ID, SHA в HELLO и повторное чтение workspace.
  Это искусственный тест, не доказательство поддержки официального 2.8.0.

Следующий этап для 2.8.0: перенести USB-интеграцию с учётом изменений
SerialConsole/PhoneAPI, регенерировать protobuf bindings, проверить дополнительные
патчи, зарегистрировать зависимости и выполнить native/firmware сборки.
