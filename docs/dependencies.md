# Закреплённое окружение сборки

Первый lock: T-Beam S3 Core, Meshtastic 2.7.26, Windows AMD64, Python 3.12.14.
Heltec V3 имеет отдельный lock на той же платформе и tools: 77 архивов и
36 wheels. Дополнительная T-Beam библиотека SensorLib ему не требуется.
Все три пользовательские опции используют один набор зависимостей; UA22,
кириллица и display timeout остаются выключенными по умолчанию.

`registry/locks/tbeam-s3-core-2.7.26-windows-amd64.json` содержит:

- ESP32 platform и семь инструментальных пакетов, включая framework и SCons;
- 70 библиотек, включая транзитивные зависимости Adafruit и Unity;
- 36 Python wheels, включая PlatformIO, protoc, nanopb generator dependencies,
  esptool dependencies и pip;
- точные версии, URL, размеры и SHA-256 каждого архива.

SHA-256 lock хранится в каталоге и попадает в план подготовки и manifest сборки.
Изменение lock требует нового подготовленного workspace. Старая команда build
с произвольными `--python`/`--platformio-core` заменена обязательным `--runtime`.

## Порядок работы

1. `prepare` создаёт checkout закреплённых firmware/protobufs и применяет патчи.
2. `fetch-dependencies` загружает только перечисленные архивы. Проверяет размер
   и SHA-256 новых и уже кешированных файлов. Повреждённый кеш вызывает ошибку;
   его повреждённый файл можно удалить вручную и повторить загрузку.
3. `bootstrap` сначала проверяет весь кеш, затем создаёт новый venv, устанавливает
   wheels через `--no-index --no-deps --only-binary --require-hashes`, запускает
   `pip check` и распаковывает PlatformIO packages. Сохраняет статус и хеши файлов.
4. `build` проверяет исходники и окружение, компилирует и повторно сверяет хеши
   окружения перед выпуском артефакта. В результат копируется `runtime.json`.

Из сверки исключены Python bytecode caches и служебный `libdeps/<environment>/integrity.dat`:
PlatformIO записывает туда список запрошенных библиотек в произвольном порядке.
Файлы внутри самих пакетов, в том числе с именем `integrity.dat`, проверяются.

Сетевые операции Python заблокированы audit hook во время bootstrap/build;
pip индексы, пользовательские Python пути и PlatformIO переменные очищаются.
Окружение не использует глобальные PlatformIO/libdeps каталоги. Это ограничение
резолвера зависимостей, а не универсальная ОС-песочница для произвольного кода.

Vendor postinstall hooks не выполняются: esptool hook ставит пакеты по диапазонам
версий. Его зависимости вместо этого входят в проверяемый venv. PlatformIO
получает исходную метаинформацию каждого пакета, поэтому распознаёт локальные
архивы без обращения к registry. Для архивов без версии записывается версия
из lock, чтобы исключить зависимость от времени распаковки.

Кеш можно переносить на другую Windows AMD64 машину с Python 3.12.14; runtime
нужно создавать заново, поскольку venv содержит абсолютные пути. Python, Git и
ОС — внешние предпосылки. Побайтовая идентичность образов не гарантируется:
upstream может включать время сборки и пути. Другие ОС требуют отдельного lock.

## Обновление сопровождающим

`scripts/resolve-build-lock.py` создаёт кандидат lock из явно указанного,
проверенного PlatformIO окружения и Python. Инструмент обращается к PlatformIO
registry, GitHub и PyPI; он не запускается пользователем автоматически.

После изменения версий нужно проверить diff, обновить SHA-256 в catalog,
загрузить зависимости в пустой кеш, установить новое окружение и собрать
новый checkout без сети. GitHub tags защищены хешами содержимого: изменение
архива по прежнему URL вызывает отказ, а не молчаливое обновление.
