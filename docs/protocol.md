# Переносимый контракт MeshMemo: USF2, профиль 1/4

Builder 0.1.0a2 формирует прошивки для MeshMemo server 0.1.0a8 и новее.
Поддержанная база пока одна: firmware `54e0d8d0ab2ff56b3a9ce967e53f79e49af560fb`.
Сервер принимает также прежние USF1 1/2 и 1/3 на модели 12. Старый сервер
не принимает новый ответ USF2; сначала обновляется сервер.

## Формат

Запросы сохраняют `USF1`, прежние operation/session/token и форматы полезной
нагрузки. Это позволяет серверу начать handshake одинаково со старой и новой
прошивкой. Новая прошивка всегда отвечает явно версионированным **USF2** длиной
112 байт. Старый ответ USF1 имеет 68 байт. Неизвестный magic, неверная длина,
reserved, operation/status и несовпадение session/token отклоняются.

Все числа little-endian. Расширение остаётся локальным protobuf bytes field 100
в ToRadio/FromRadio; поле не является MeshPacket и не пересылается по радио.

| Offset | Размер | Значение |
| --- | --- | --- |
| 0 | 4 | `USF2` |
| 4 | 1 | Operation с установленным битом `0x80` |
| 5 | 1 | Status: прежние значения 0–8 |
| 6 | 2 | Reserved = 0 |
| 8 | 4 | Session |
| 12 | 4 | Token |
| 16 | 2 | Максимум текста replay: 192 байта |
| 18 | 1 | Profile = 1 |
| 19 | 1 | Patch revision = 4 |
| 20 | 4 | Настоящий `HW_VENDOR` платы |
| 24 | 4 | Queue free; пока 0, не обещает ёмкость очереди |
| 28 | 40 | ASCII commit базовой firmware |
| 68 | 4 | Маска реализованных операций |
| 72 | 2 | Максимальный запрос: 256 байт с заголовком |
| 74 | 2 | Максимум control payload: 100 байт |
| 76 | 2 | Максимум encrypted payload: 208 байт |
| 78 | 2 | Локальный transport: 1 = native USB CDC, 2 = USB–UART console |
| 80 | 32 | Build ID, SHA-256 разрешённого плана сборки |

Биты операций: `1 << (operation - 1)`; HELLO=1, REPLAY=2, ABORT=3, CONTROL=4,
ENCRYPTED_REPLY=5. Полный профиль имеет маску `0x1f`. Сервер требует HELLO,
REPLAY, ABORT, CONTROL; без ENCRYPTED_REPLY он блокирует server-channel replies
до передачи команды. Диагностический профиль 0/4 объявляет маску `0x05` и
нулевые пределы radio payload; он не даёт права отправки.

## Совместимость и идентичность

Для USF2 сервер проверяет базовый commit, версию, профиль/revision, операции,
лимиты, допустимый локальный transport, ненулевую модель и build ID. Ограничения
`hardware_model == 12` для USF2 нет. Для старых USF1 1/2 и 1/3 прежняя проверка
модели сохранена; их операции определяются по проверенной revision.

Build ID вычисляется из канонического JSON плана (sort_keys, compact separators),
включая плату, исходники, патчи, опции, версию builder и dependency lock.
Информационные hardware status исключены. Хеш записывается в `plan.build_id`
и генерируемый `UsbSfBuild.h`. Compile-time assertion сверяет реальный HW_VENDOR
с моделью реестра. Изменение платы или опций меняет ID. Это идентификатор входов,
не подпись устройства и не SHA-256 готового бинарника; хеш образа хранится отдельно.

После HELLO сервер фиксирует capability identity. Изменение модели, build ID,
операций, версии или лимитов в той же сессии закрывает её. Queue free и status
могут изменяться. Точные повторы token, conflict/stale/session handling и
правила повторной попытки после BUSY/отказа сохраняются.

## Транспорт и радио

Hook по умолчанию остаётся запрещён в PhoneAPI. Его разрешает только SerialConsole
после обычной protobuf configuration session. Выбор транспорта явный для платы:
T-Beam S3 Core — native USB CDC, Heltec V3 — console через USB–UART.
Наличие CP2102 у V3 подтверждено [спецификацией производителя](https://heltec.org/project/wifi-lora-32-v3/);
этот профиль не относится к Heltec V4.
Несовпадение CDC-настроек с выбранным transport останавливает компиляцию.
USER_DEBUG_PORT и RP2040_SLOW_CLOCK не разрешаются этим профилем. BLE/TCP/HTTP
не получают расширение. Проверка поведения физического порта требует устройства.

Радиообработчик сохраняет проверки конфигурации, private channel context,
адресов, размеров, airtime, очереди и запрет параллельного встроенного S&F.
Host-encrypted replies требуют доверенного локального сервера: firmware не
проверяет plaintext шифротекста. Capabilities не включают replay автоматически.

SHA-256 вынесен в `UsbSfSha256.h`; текущий проверяемый backend — mbedTLS для
ESP32. Другие архитектуры получают явную ошибку компиляции до добавления и
проверки их backend. Наличие общего wire contract не означает поддержку всех MCU.
